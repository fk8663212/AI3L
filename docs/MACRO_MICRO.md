# Macro／Micro 正式流程

本功能位於 `feature/macro-micro-integration`，從已修正錄音與第六階段 AI 的版本延伸。原 HTML Demo 繼續獨立保留；正式學習頁使用學生自己的已確認概念及 AI 輸出，沒有固定「入口、攤位、美食」資料。

## 老師與學生怎麼使用

1. 在老師後台設定 AI Key、發布任務並建立測試學生代碼，照原七階段流程操作。
2. 第 5 階段先審核 AI 擴充概念圖，完成需要的節點與關係調整，再按「建立 Macro／Micro 講述架構」。AI 依內容安排段落，通常 3–5 段，最多 6 段。
3. 點選 Macro 段落會切換該段的 Micro 子圖。可用上一段、下一段、左右方向鍵，也可切回單層概念圖。
4. 「調整段落名稱與順序」可以改中英文名稱、上移／下移、增刪段落，以及選擇每段要談的已確認概念。每個概念至少需安排到一段；同一概念可在開場和總結重複使用。
5. 第 6 階段先保存至少三個自己的句子，再取得提示。AI 會同時準備原有逐句分級提示，以及各 Macro 段落的英文關鍵詞與句首。點不同段落時，子圖與語言提示一起切換。
6. 調整講述段落後需重新取得提示；已保存句子與原有研究紀錄保留。概念圖內容變更後，舊的分段會標示需要重新安排；只移動節點位置不需重建。
7. 確認收音正常後保存練習，進入後測。後測會隱藏所有先前的圖與提示，伺服器也不接受建立／編輯／瀏覽講述段落的操作。

既有停留在第 6 階段的學生，可直接根據第 5 階段已確認的概念建立架構，不必倒退階段。已完成或進入後測的記錄不會自動補寫新資料；要完整比較新版流程，建議使用新的測試代碼。

原有單層流程仍保留，尚未建立講述架構的紀錄可以沿用原本操作。系統記錄學生使用哪種視圖，但不自動分派研究組別。

## 資料與研究紀錄

- `speaking_outline`：保存在第 5 階段，包含段落順序、中英文名稱、各段節點代號、AI 原始分段、學生修改時間、來源概念圖內容簽章及 `macro-micro-v1` 版本。
- Micro 直接從已確認概念圖抽取節點與關係，不另造新的概念或邊；伺服器拒絕未知節點、重複段落代號、空段落與漏掉的概念。
- `sentence_scaffold`：保留原有逐句分級提示，另加入 `paragraphHints` 與所依據的 `speakingOutlineId`。段落修改期間尚未完成的 AI 輸出會被丟棄，避免錯套提示。
- `speaking_progress` 與 `speaking_navigation` 訊息：保存最後選取的段落、單層／雙層視圖、提示是否實際顯示，以及所依據的架構版本；重新整理可回到選取的段落。
- 老師的完整學習歷程提供唯讀雙層圖，切換不會寫入學生操作紀錄。研究 JSON 匯出包含原始與已被取代的架構、AI 執行與互動紀錄。
- 新 AI 呼叫沿用任務指定的供應商、模型、API Key、逾時／重試及稽核機制。「Prompt 與階段」可查看講述架構的固定提示契約。

資料使用既有 artifact、message 與 ai_run 資料表，不需要新增 SQL migration。既有資料與原始圖片、錄音不會被改寫。

## 驗證

```bash
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

測試包含伺服器同意／階段限制、概念來源驗證、段落修改、提示版本、研究匯出與後測隱藏；瀏覽器測試使用隔離的範例學生，驗證桌面與手機的子圖／提示同步與保存。AI 自動化測試使用替身；真實 Gemini API 的額外驗證使用固定範例，不重送現有學生資料。
