# 活動背景知識補述

學生先自行畫概念圖，之後上傳的圖會直接作為 AI 輸入。「自行繪製」不代表這張圖永遠不交給 AI；第 3 階段是學生繪製，第 5 階段才進行整合擴充。

## 第 5 階段使用的資料

1. 情境圖在前面先經 AI 辨識，學生接受或修改的詞彙會帶入第 5 階段；移除的辨識項目不作為已確認詞彙。
2. 學生上傳的手繪概念圖，在第 5 階段直接以圖片附件送給模型，讀取節點、箭頭與關係詞。
3. 任務名稱及老師填寫的「活動簡介／研究任務摘要」提供活動背景，讓模型運用已有知識，補充學生可能省略的相關內容。

目前情境圖的資訊是透過已確認詞彙整合，並非第 5 階段再同時附上情境原圖。即使老師自訂 Prompt 沒有寫出相關變數，系統仍補上必要的手繪圖附件資訊、已確認詞彙與活動簡介，並在 Prompt 審計中列出。

## 學生怎麼篩選

例如圖上只有「我的旅行 → 礁溪」，模型可根據相關地方知識提出「溫泉」候選，再問學生是否有泡溫泉或相關體驗。這是喚起回憶的建議，不是斷言學生已經泡湯；模型輸入沒有固定綁定礁溪或市場故事。

- 原有手繪內容維持學生來源；AI 新增項目維持 AI 來源及橘色。
- 超出作品／已確認詞彙、由背景知識補出的概念與關係，顯示「AI 背景知識補述」、建議理由與確認問題。
- 學生逐項按「保留」或「移除」。移除概念也會移除相連關係；未明確保留的背景補述不會自動加入最後概念圖。
- 保留後仍保存 AI 來源，手動改名或改關係詞也不會把 AI 補述洗成學生原有概念。
- 因果內容仍區分可能原因／已知原因、建議行動／已執行行動，以及預期／已觀察結果。學生保留建議不等於證明因果；流程候選也不等於學生一定做過。

只有保留後的概念與關係能進入 Macro／Micro 和句型鷹架，模型的篩選問題與補述理由不當成學生講稿。最後錄音繼續只提供最後確認的圖，不額外顯示這些篩選問題、句首或示範句。

## 已有圖的學生

現有已生成的圖不會自動重跑，舊資料也不批次補標記。在第 5 階段按「重新生成概念圖與補述」，即可根據目前任務背景取得新圖；重新生成後必須重新篩選，先前決定不會自動套用到新候選，即使模型重用同一個項目 id。需要時再重新建立段落與提示。

已進入後續階段的測試學生，可由老師依既有「管理員階段覆寫」流程退回第 5 階段，或使用新的測試代碼。重新生成的舊圖與審核紀錄以已取代方式保留，原始上傳圖不變。

## 研究紀錄

新生成圖記錄 `enrichmentPolicy: topic-knowledge-v1` 及實際使用的任務名稱／活動簡介快照。背景補述項目的 `enrichment` 包含 `kind: background_knowledge`、`reasonZh`、`questionZh`；模型不能自行宣稱已經取得學生確認。

學生明確保留後，由伺服器加入 `confirmedByStudent: true`，並在概念審核訊息保存 `confirmedEnrichmentIds` 與 `sourceArtifactId`。確認必須對應學生看到的那一版建議；重新生成後，上一版的確認不會套用到重用相同 id 的新內容。遺漏明確保留清單時，背景補述預設排除；舊圖沒有相關欄位時沿用原本審核方式。

欄位保存在既有 artifact 與 message JSON，模型執行仍保存供應商、模型、Prompt 雜湊及用量，無新增 SQL migration。既有研究 JSON 匯出會保留原始建議、學生篩選、手動修改及已被取代的版本；教師自訂 Prompt 的原文不覆寫。
