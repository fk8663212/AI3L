# 因果／問題解決順序模板

第三種模板已接入正式七階段流程，使用學生已確認的概念圖與自己的英文句子。與「空間／導覽」、「時間／流程」共用 Macro／Micro 元件與資料保存方式，沒有固定問題、原因或解法。

## 老師怎麼設定

1. 開啟 <http://localhost:3000/admin/login>，登入後進入「研究任務」。
2. 建立新草稿；若要沿用已發布任務，先按「建立 vN 草稿」。原版本與已作答學生維持原設定。
3. 填寫任務名稱、摘要，在「講述架構模板」選「因果／問題解決順序」。唯一識別名稱可留空；摘要至少 10 個字元，沿用原規則，不送入 AI。
4. 檢查七階段指示。切換模板只更新原本的預設文字，保留老師自訂內容；按「套用模板的階段說明」可重設全部階段說明。
5. 保存草稿，確認 AI Key／模型，發布後建立新的學生代碼。發布後模板鎖定，不能直接改掉原研究版本。

適用情境包含工程故障排除、案例分析、環境問題及 SDGs 專案探討。AI 分段以任務名稱及學生已確認的概念、關係為依據，不會根據摘要自行補出研究事實。

## 學生怎麼使用

- 第 2、3 階段：畫出自己觀察到的情況，在手繪概念圖用關係詞表達知道的原因、影響或處理方式，區分已知與推測。
- 第 4、5 階段：逐項審核 AI 辨識的詞彙與擴充關係。缺乏證據的原因、沒有做過的行動不能當作事實保留。
- 第 5 階段：確認概念圖後按「建立 Macro／Micro 講述架構」。選不同段落會切換對應的 Micro 子圖；可改中英文名稱、順序、增刪段落及調整概念分組。
- 第 6 階段：先保存至少三個自己的英文句子，再取得分級提示及各段的關鍵詞、句首。切換 Macro 時，子圖與提示一起切換。
- 第 7 階段：隱藏之前的圖、段落、缺漏提醒與語言提示，獨立口說。伺服器也會阻擋講述架構操作。

修改段落後必須重新取得提示；已保存的學生句子仍保留。只調整概念圖的節點位置不需要重建架構，改動內容或關係則需要重建。

## AI 如何安排與提示

有解決策略或行動的內容使用 `organization: problem_solution`，建議路徑為：

問題現況與背景 → 核心成因分析（有依據時）→ 解決策略與行動 → 預期成效或已觀察結果（有資料時）。

只提供原因與影響、沒有解法的內容使用 `organization: causal`：

現象與背景 → 有依據的原因 → 影響與結果。

AI 依學生內容命名與分組，通常 3–5 段、最多 6 段；資料少時可減少，不強迫湊滿四段。Micro 只抽取已確認節點與兩端都在該段的既有關係，保留方向、來源及原關係詞。

規則會要求 AI：

- 不能只靠圖像、時間先後、共現、圖上位置或箭頭方向斷定因果，必須有已確認的關係詞或明確資料支持。
- 區分「可能原因」與「已確認原因」、「建議行動」與「已執行行動」；不捏造成因、解法、成功成效或檢驗數字。
- 預期成效不能寫成已觀察結果，段落名稱與英文提示都須保留這個差別。
- 缺少必要依據時保存 `informationGaps`，在畫面顯示待補充提醒；沒有資料的段落略過，純因果內容不強迫提出解法。

例如固定測試案例中，學生已確認「不清楚的標示 → 促成 → 垃圾混放」，成因段落可顯示 `unclear labels` 與 `Because the labels are unclear, …`。學生提出「新標示 → 可能改善 → 分類」，預期成效段落可顯示 `This could help …`，不會直接寫成已經成功改善。

已確認因果才使用 Because／As a result；已有觀察證據的結果才使用 The result was …。可能原因使用 One possible cause is …；解法可用 To solve this problem, …。句首保留空白，逐句示範、翻譯與連接詞也套用相同的證據與語氣規則。

這些語意規則由 AI 提示與學生審核共同落實；結構驗證能拒絕未知節點、錯誤模板或組織種類，不能自動判定學生提供的因果證據是否充分。

## 保存與相容性

- 任務保存 `config.speakingTemplate: { id: "problem_solution", version: "1.0.0" }`。
- `speaking_outline` 使用 `macro-micro-v2`，保存模板快照、`organization`、`informationGaps`、AI 原始分段、學生修改與來源概念圖簽章。
- 第 5 階段須建立匹配模板的架構；第 6 階段檢查提示所對應的架構 ID。舊模板、過時架構及 AI 執行中被取代的資料不能用來完成階段。
- 老師完整學習歷程可唯讀查看架構、Micro 與提醒，研究 JSON 匯出保留版本及互動紀錄。「Prompt 與階段」包含本模板的實際規則。
- 使用既有 JSON 欄位，不需要 SQL migration。既有空間、時間與未指定模板的研究資料、圖片及音檔不改寫。
