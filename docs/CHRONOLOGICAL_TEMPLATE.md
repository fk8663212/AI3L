# 時間／流程順序模板

此模板已接入正式七階段流程，使用學生的手繪圖、已確認概念與自己的句子；風車只是測試案例，程式沒有固定風車內容。

## 老師怎麼設定

1. 開啟老師後台的「研究任務」，建立新草稿；若沿用已發布任務，先按「建立下一版草稿」。
2. 填入這次活動或事件的任務名稱與摘要，在「講述架構模板」選「時間／流程順序」。摘要沿用原規則，只顯示於介面，不送入 AI。
3. 檢查七階段學生指示。切換模板會更新原本的預設說明，保留老師自訂的內容；需要全部重設時，可按「套用模板的階段說明」。前、後測文字不列出分段骨架或英文句首。
4. 檢查 AI 設定及「Prompt 與階段」，保存、發布，再建立新的學生代碼。發布後模板與任務一起鎖定，更換模板須建立新研究版本。

新任務也可選「空間／導覽順序」。舊任務沒有模板欄位時，顯示「原有講述架構（未指定模板）」，保留原有行為，不會替舊研究紀錄補分類。

## 學生怎麼使用

- 第 2、3 階段：畫出活動或事件，可用多個畫面表達不同階段；手繪概念圖標出已知的動作、先後與結果。
- 第 4、5 階段：審核 AI 辨識與擴充內容，保留真正符合圖像或經驗的概念與關係。
- 第 5 階段：確認概念圖後按「建立 Macro／Micro 講述架構」。已指定模板的任務須完成此步驟，才能前進。
- 第 6 階段：先保存至少三個自己的英文句子，再取得提示。點不同 Macro，會一起切換 Micro、關鍵詞與句首。
- 第 7 階段：隱藏先前的圖與提示，獨立口說。伺服器也會阻擋建立、修改與瀏覽架構的操作。

學生仍可改段落中英文名稱、順序、增刪段落與調整節點分組。修改後須重新取得提示，已保存句子保留。

## AI 如何安排

實作、實驗或料理採 `procedural`：

準備工作 → 核心操作／步驟（可分多段）→ 突發狀況與排除（有資料時）→ 產出與檢驗（有依據時）。

歷史或事件敘述採 `chronological`：

背景／起點 → 事件先後發展 → 結果／回顧。

段落依內容調整，通常 3–5 段、最多 6 段。Micro 僅引用學生已確認的節點與關係；節點在陣列中的順序、圖上左右位置都不視為時間證據。沒有突發狀況就略過；缺少先後或結果資料時，在「建立架構時的待補充提醒」列出需要確認的內容，不編造步驟、日期、故障或成效。

例如學生已確認「葉片 → 連接 → 軸心」，選「組裝步驟」時可顯示 `blade`、`axle` 與 `Next, we attach …`。實際詞彙與句首由任務 AI 依該學生的資料產生，使用 First、Next、Then、Finally 或符合事件內容的時間銜接，保留空白讓學生自己完成。

## 保存與相容性

- 任務 `config.speakingTemplate` 保存種類與版本，例如 `chronological@1.0.0`，使用既有 JSON 欄位，沒有新增資料表或 SQL migration。
- `speaking_outline` 保存模板快照、`organization`、`informationGaps`、AI 原始分段與學生修改；設定模板的新架構使用 `macro-micro-v2`。
- 句型提示保存對應的架構 ID 與模板快照。概念圖、段落或模板版本不一致時，舊提示不能用來完成階段；AI 執行途中資料變更，過時輸出會被丟棄。
- 老師完整歷程可唯讀查看模板、子圖及提醒。研究 JSON 匯出保留各版本與互動紀錄。
- 舊任務與原本未指定模板的架構仍可使用原流程，既有圖片、音檔與紀錄不改寫。

## 驗證

```bash
npm run typecheck
npm test
npm run test:e2e -- --workers=1
```

自動化測試以隔離資料驗證老師設定、發布鎖定、版本相容、分段／提示保存、來源驗證、後測隱藏與桌面／手機切換。瀏覽器測試不呼叫 AI；額外的真實 API 驗證只使用固定範例。
